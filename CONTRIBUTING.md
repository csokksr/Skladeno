# Як вносити зміни

«Складено» — статичний сайт-тренажер для підготовки до НМТ (українська мова, математика, історія України, англійська). Він збирається Python-скриптами з `src/` в один HTML-файл. Структуру проєкту й формат даних описує [README.md](README.md), правила роботи — [CLAUDE.md](CLAUDE.md).

## Що потрібно

- Python 3.12 (для збірки достатньо стандартної бібліотеки), Node.js 20 або новіший (для тестів).
- Лише для скриптів, що читають PDF чи зображення (`zno_keycheck.py`, `zno2_keycheck.py`, `zno_images.py`): `python -m pip install -r requirements.txt`.

## Команди

```bash
python -I tools/build.py                       # зібрати dist/skladeno-nmt.html
python -I tools/validate.py                    # завдання, посилання, тексти, бюджет коду; має завершитися «OK»
python -I tools/check_schema.py                # формат модулів src/content/*.json
python -I tools/check_text.py                  # механічні помилки в тексті інтерфейсу
node tools/changelog.js --check                # журнал змін відповідає сторінці «Про сайт» (без --check перезаписує файл)
node tests/run.js                              # регресійні тести сторінки (потрібна свіжа збірка)
python -m unittest discover -s tests/py -v     # тести скриптів Python
npm ci                                         # один раз: інструменти розробки (лінтер, типи, Playwright, Lighthouse, prettier, esbuild)
npm run format:write                           # форматування джерел перед комітом (npm run format лише перевіряє)
node tools/lint.js                             # ESLint; імена верхнього рівня збираються з усіх модулів
node tools/typecheck.js                        # tsc checkJs без відомого шуму
npx playwright install chromium                # один раз; далі: npx playwright test (комп'ютер, телефон і axe)
node tools/coverage.js [--list]                # частка іменованих функцій сторінки, яких торкаються тести (поріг у CI 45%)
python -I tools/check_links.py [--strict]      # чи відкриваються зовнішні посилання (потрібна мережа, у CI раз на тиждень)
```

Перед запитом на злиття мають проходити збірка, `validate.py`, `check_schema.py`, `check_text.py`, `node tests/run.js` і тести Python. CI запускає все це на Linux і Windows.

## Правила, які не обговорюються

- **Не пиши автоматично згенерованого змісту й не вигадуй завдань.** Завдання історії, української, математики й англійської беруться лише з офіційних ЗНО/НМТ. Ключі звіряють із аркушами УЦОЯО; не пиши, що ключ перевірено, не запустивши `zno_keycheck.py` чи `zno2_keycheck.py`.
- **Мову й факти звіряй із джерелами проєкту:** правопис 2026 (`research/pravopys` у локальній копії власника, у git він не входить), офіційний перелік наголосів, програма історії (`sources/program/hist.md`). Скіл `source-check` робить це покроково.
- **Правь `src/` і генератори `tools/content_*.py`, а не `dist/`.** Точкові виправлення завдань — окремим модулем `src/content/NN-*.json` (ключі `patch`, `replace`, `drop` та інші, див. README); модулі застосовуються за алфавітом назв.
- **Нові завантаження з інтернету** (завдання, PDF) лише з явного дозволу власника проєкту.
- **Мова текстів:** інтерфейс і документація українською, без канцеляриту й без «AI-слопу».

## Новий модуль сайту

1. Створи `src/modules/NN-назва.js`. Модулі підключаються після `src/app.js` за алфавітом; веб-шар `src/web/90-web.js` вантажиться останнім і лише у веб-збірці.
2. Розширюй наявні функції обгортками (`const xBase=f;f=function(){xBase();…}`) і завжди викликай базову функцію.
3. Додай рядок про модуль у таблицю структури в README: `validate.py` відхилить модуль без опису.
4. **Перегляд сторінки не пише в прогрес.** Запис (`pSave()`, `save()`) лише з дії користувача.
5. **Увесь текст користувача і значення з імпорту екрануй через `esc()`** і не вставляй їх в атрибути чи `onclick` напряму.
6. Нове поле в прогресі `P` має проходити очищення при імпорті, відновленні й завантаженні: див. `src/modules/15-import-guard.js` (`guardPlatform`, `guardRun`) і `extNormal` у `src/modules/84-rhythm.js`.
7. Додай тест у `tests/cases/` (стенд `tests/harness.js` із підмінним DOM; перший рядок `// LS: файл` підвантажує `localStorage`, `// TZ: зона` задає часовий пояс). Перевіряй гілки, а не лише успішний шлях.
8. Додай запис у `ABOUT_CHANGES` (`src/modules/79-about.js`; нові зверху, у кожного лише день і місяць) і запусти `node tools/changelog.js`. Коли історія переходить на новий рік, змінюй `ABOUT_YEAR` у тому ж файлі.
9. Дотримуйся бюджету коду: `validate.py` не пропустить сторінку, що перевищила межу JS чи CSS. Піднімай межу свідомо, з поясненням у коментарі, а не «бо не влізло».

## Запит на злиття

- Один запит — одна тема. У описі напиши, що змінилося й що **не** перевірено.
- Не змінюй згенеровані файли вручну (`dist/`, `src/history-bank.json`, `sources/zno/bank.json`): їх перезаписують скрипти, а в Claude Code таку правку блокує хук `.claude/settings.json`; для звичайних запитів на злиття блокування немає, тож перевіряє рецензент (змінений `dist/` чи згенерований файл без зміни генератора відхиляється).
- Публікація артефакта (`/publish-web`) — окрема дія власника, не частина запиту на злиття.
